# E0001: syntax error

The parser found a token it did not expect.

## Example

```hugin fail=E0001
edge : int -> int -> rel
path : int -> int -> rel.
```

## Why this is an error

Every item, whether a declaration, definition, rule, query or directive, ends with a period. When the
parser meets a token that cannot continue the current item, it reports what it expected there and what it
found. If the next item starts in column 0 of a later line, the parser inserts the missing period before
it, and `hugin fix` adds the period to the file. Otherwise the parser skips the rest of the item and
resumes at the next one, so that one mistake does not hide the errors after it. The item with the error
is kept with the parts that parsed, but it is not elaborated, and other items that use the names it
declares are not reported again.

Common forms have a message of their own: `::` instead of `:` in a declaration (`f :: int -> int.`), a
`:` too many in a definition (`x := 5.`), `=` in a record type or `:` in a record value.

## How to fix it

End the first declaration with a period:

```hugin
edge : int -> int -> rel.
path : int -> int -> rel.
```
