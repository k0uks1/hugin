# E0109: ambiguous name

A name that two `%use` items open for different declarations is used, and not all of them are meta
constants.

## Example

```hugin fail=E0109
graph : Type = { node : type, edge : node -> node -> rel }.
tc (g : graph) = {
  path : g.node -> g.node -> rel.
  path X Y :- g.edge X Y.
}.
city : type. berlin, paris : city.
road : city -> city -> rel.
road berlin paris.
rail : city -> city -> rel.
%use (tc { node = city, edge = road }).
%use (tc { node = city, edge = rail }).
?- path berlin X.
```

## Why this is an error

`%use m.` opens the fields of `m` as names of the file. When two opened modules have a field of the same
name that denotes different declarations, a use of the name could mean either. If they are all meta
constants, the name is overloaded and the types choose one (E0932 if several fit, E0933 if none does);
an object constant (a relation, an object type or constructor, also one of a module instance) is never
chosen so, and the use is rejected. Opening the same declaration twice is not an error, and a
declaration of the file shadows opened names. Here the two instances of `tc` both have a relation
`path`. See [Modules](https://k0uks1.github.io/hugin/reference/modules.html#opening-modules).

## How to fix it

Open only one of the modules, and refer to the other by a name:

```hugin
graph : Type = { node : type, edge : node -> node -> rel }.
tc (g : graph) = {
  path : g.node -> g.node -> rel.
  path X Y :- g.edge X Y.
}.
city : type. berlin, paris : city.
road : city -> city -> rel.
road berlin paris.
rail : city -> city -> rel.
%use (tc { node = city, edge = road }).
byRail = tc { node = city, edge = rail }.
?- path berlin X.
?- byRail.path berlin X.
```

Or open only the fields that are needed from one of the modules, with a list of names, `%use m (x, y).`.
