# E0911: non-covering clauses

The clauses of a meta function do not cover every case.

## Example

```hugin fail=E0911 elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
pred : nat -> nat.
pred (suc N) = N.
```

## Why this is an error

Meta functions are total: every argument must match some clause, so that compile-time evaluation never
gets stuck. The diagnostic shows the first of the most general missing patterns and the number of the
others: for `f 0 0 = 0.` it shows `f _ (_ + 1)` "and 1 more" (the other is `f (_ + 1) _`). They are
sorted argument by argument, `_` first, constructors in declaration order, and do not depend on the order
of the clauses' splits. The editor's "add missing clauses" adds one clause per pattern. Cases that are
impossible by typing need no clause, and neither do cases in which an argument would have a type none of
whose constructors can occur.

A meta declaration that is neither an inductive family nor a constructor declares a function, also
without clauses. No clauses do not cover its arguments either, unless one of them has an empty type, so
a declaration alone does not assume a value:

```hugin fail=E0911 elaborate
boom : (A : Type) -> A.
```

A constant without a value is a *postulate*, declared as such: `boom : (A : Type) -> A = %postulate.`
([Functions](https://k0uks1.github.io/hugin/reference/meta/functions.html#postulates)).

## How to fix it

Add a clause for the missing case:

```hugin elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
pred : nat -> nat.
pred zero = zero.
pred (suc N) = N.
```
