# E0927: ill-typed abstraction

A `match` abstracts its scrutinee in the expected type, and a `rewrite` abstracts the left side of its
equation; here the expected type with the term abstracted is ill-typed.

## Example

```hugin fail=E0927
%use "std/eq".
%use "std/nat".
p : nat -> Type.
q : (n : nat) -> p n -> Type.
bad : (n : nat) -> (h : p (plus 0 n)) -> q (plus 0 n) h.
bad N H = match plus 0 N with
  | 0 => ?
  | K + 1 => ?.
```

## Why this is an error

`match e with …` replaces every occurrence of `e` in the normal form of the goal by a new variable `y`,
and checks each branch against the goal with the branch's pattern in place of `y` (see
[`match` and `rewrite`](https://k0uks1.github.io/hugin/reference/meta/match.html#ill-typed-abstractions)).
Only the goal is abstracted, not the types of the variables in scope. Here the goal is
`q (plus 0 N) H`; abstracted, it becomes `q y H`. But `q y` expects an argument of type `p y`, and the
type of `H` is still `p (plus 0 N)`: `H` depends on `plus 0 N`, which is not replaced in its type. The
message names the abstracted term, the goal before and after, and the argument that no longer fits.

## How to fix it

Abstract the term together with what depends on it: write a `where`-local function whose type
generalises both, and match there.

```hugin
%use "std/eq".
%use "std/nat".
p : nat -> Type.
q : (n : nat) -> p n -> Type.
mk : (n : nat) -> (h : p n) -> q n h.
fill : (m : nat) -> (h : p m) -> q m h.
fill 0 H = mk 0 H.
fill (K + 1) H = mk (K + 1) H.
good : (n : nat) -> (h : p (plus 0 n)) -> q (plus 0 n) h.
good N H = fill (plus 0 N) H.
```

Here `fill` takes the term and the hypothesis as arguments, so they are generalised together; its
clauses split `M`, and the type of `H` follows.
