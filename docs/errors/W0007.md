# W0007: variable bound by name through a hole

A variable of a quoted rule's head is bound only by the name that the data in a hole of the body uses.

## Example

```hugin fail=W0007
%use "std/reflect".
person : type. city : type.
lives : person -> city -> rel.
born : city -> rel.
born_where : formula -> rule.
born_where F = '( born C :- $F ).
```

## Why this is reported

A variable of reflected data is the variable of the rule with the same name, so the head's `C` is bound
only if the formula in `$F` happens to name a variable `C`. No formula of the quote binds `C`, and the
hole is a `formula`, so the quote cannot be typed with `C`: a piece that uses `C` in a column of another
type is found only when the rule is reflected. Lint name: `hole_capture`. See
[Reflection](https://k0uks1.github.io/hugin/reflection.html#typed-variables).

## How to fix it

Pass the variable to the code that builds the hole's data, as a typed variable made by `qvar`:

```hugin
%use "std/reflect".
person : type. city : type.
lives : person -> city -> rel.
born : city -> rel.
born_where : (quoted city -> formula) -> rule.
born_where F = '( born $c :- $(F c) )
  where c : quoted city = qvar "c".
```
