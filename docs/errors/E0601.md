# E0601: stratification cycle through negation

A cycle of the dependency graph contains a negative edge.

## Example

```hugin fail=E0601
move : int -> int -> rel.
move 1 2. move 2 3.
win : int -> rel.
win X :- move X Y, not win Y.
```

## Why this is an error

Negation and aggregation need the negated relation to be complete before they are evaluated, so they must
not occur in a recursive cycle: the program is evaluated stratum by stratum. Here a position is winning
if a move leads to a position that is not winning, so `win` depends on itself through a negation. A rule
that builds a constructor term in its head makes the constructor depend on what the rule reads, which can
also close a cycle (see [Facts and
identity](https://k0uks1.github.io/hugin/reference/object/facts.html#facts-derived-in-other-components)).

## How to fix it

Negate a relation that does not depend on `win`:

```hugin
move : int -> int -> rel.
move 1 2. move 2 3.
stuck : int -> rel.
stuck Y :- move _ Y, not move Y _.
win : int -> rel.
win X :- move X Y, stuck Y.
```
