A fact about a module whose facts are part of the program can be proved by running the program. decide n is a lemma of std/semantics: if holds n p a, n rounds of naive evaluation of p, finds the fact a, then p derives it. The evaluation runs in the type checker, and tt is the proof that its result is true.

The evaluation is certifying: every fact it finds carries its derivation, so the lemma is proved, not assumed. If the rounds are too few, the result is false, the proof obligation is the empty type, and tt is rejected; the wrong version below asks for two rounds where three are needed.

How far this goes:

  • It is sound, not complete. holds may be false for a derived fact: input relations contribute no facts, rules with negation or aggregates derive nothing in it, and a rule that binds a variable only in a comparison is not evaluated.
  • It proves facts, not their absence. For stratified programs, decidePerfect of std/certify decides membership in the perfect model both ways, with a model check for the facts not found.
  • It costs compile time: every decide runs the evaluation once, when the definition is checked.

What is proved. trip derives path berlin rome, from every input database. What is trusted. Adequacy, and the meta-level evaluator that computes holds; the soundness of holds itself is a proved lemma.
