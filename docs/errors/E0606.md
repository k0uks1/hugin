# E0606: type-inconsistent rule

A rule reads a bound column of a relation of its own recursive component in a way that is not monotone.

## Example

```hugin fail=E0606
node : type = string.
edge : node -> node -> int -> rel.
source : node -> rel.
edge "a" "b" 1. source "a".
dist : (v : node) -> (d : min int) -> rel.
dist S 0 :- source S.
dist W (C - D) :- dist V D, edge V W C.
```

## Why this is an error

In the recursion of a bound relation, keeping only the best value per key is exact only if improving a
value read from a bound column improves the head, or keeps the body true (Kaminski et al. 2017; Berent et
al. 2022, Definition 4). Such a value must occur in exactly one atom. Elsewhere it may occur only in a
linear term with non-zero integer coefficients, in the bound column of a bound head and in the
comparisons `<`, `<=`, `>` and `>=`. It must occur in the improving direction: in a `min` head, or on the
smaller side of a comparison, with a positive coefficient if it comes from a `min` column and a negative
one if it comes from a `max` column, and dually for a `max` head. Here a larger distance `D` gives a
smaller head value `C - D`. Values of bound relations of earlier components are complete, so they are
plain integers. See [Bound
columns](https://k0uks1.github.io/hugin/object/bound-columns.html#type-consistency).

## How to fix it

Add the distance with a positive coefficient:

```hugin
node : type = string.
edge : node -> node -> int -> rel.
source : node -> rel.
edge "a" "b" 1. source "a".
dist : (v : node) -> (d : min int) -> rel.
dist S 0 :- source S.
dist W (D + C) :- dist V D, edge V W C.
```
