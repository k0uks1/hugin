# W0009: inexact clause

A clause of a meta function does not hold definitionally: an application that matches its patterns may
not evaluate by it.

## Example

```hugin fail=W0009 elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
bool : Type.
true : bool.
false : bool.
gg : nat -> nat -> bool.
gg zero zero = true.
gg _ (suc _) = false.
gg (suc _) zero = true.
```

## Why this is reported

An application of a function defined by clauses evaluates by its case tree, which splits on the leftmost
constructor pattern of the first clause that may still apply ([Evaluation](../meta/clauses.md#evaluation)).
Here the first clause makes the tree split on the first argument, so the second clause is used for two
cases, `gg zero (suc _)` and `gg (suc _) (suc _)`, and `gg X (suc zero)` does not evaluate while `X` is a
variable, although every clause that can match it gives `false`. A clause holds definitionally if the
tree uses it for exactly one case, and that case is the clause's own patterns.

The lint `inexact_clauses` is off by default, like Agda's `--exact-split`: turn it on with
`-W inexact_clauses` (or `-D inexact_clauses`). The function is correct either way; the lint only matters
where an application to arguments that are not yet known must evaluate, for example in a type.

## How to fix it

Write the clause's cases as separate clauses, or put it before the clauses that make the tree split
elsewhere:

```hugin elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
bool : Type.
true : bool.
false : bool.
gg : nat -> nat -> bool.
gg _ (suc _) = false.
gg zero zero = true.
gg (suc _) zero = true.
```
