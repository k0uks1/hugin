# E0942: rule that `programOf` cannot reify

A rule of the module that `programOf` reifies uses a form that the program values of `std/semantics`
do not model, or a variable whose type is not known.

## Example

```hugin fail=E0942
%use "std/semantics".
%use "std/quote".
graph2 : Type = { node : type, edge : node -> node -> rel }.
linked (g : graph2) = {
  touches : g.node -> rel.
  touches X :- g.edge X _ ; g.edge _ X.
}.
p : graph2 -> program = programOf linked.
```

## Why this is an error

`std/semantics` models the rules of stratified Datalog (see
[`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html) and
[`std/strata`](https://k0uks1.github.io/hugin/reference/std/strata.html)): atoms, comparisons, negated
atoms and aggregates in their bodies, terms built from variables, literals, constructor terms and the
object level's integer arithmetic, and heads with their nested facts. It has no disjunction and no
bound columns, it counts, adds and orders integers only, and it does not interpret floats, string concatenation, ascriptions,
projections and updates. A constructor term of a constant that the module itself declares has no code
outside an instance of the module, so the data cannot describe it. Each variable of a rule needs an
object type: the type object typing gave it, or the type of a column it stands in.

## How to fix it

Prove the property about a module whose rules stay in the fragment, for example with one rule per
alternative of the disjunction:

```hugin
%use "std/semantics".
%use "std/quote".
graph2 : Type = { node : type, edge : node -> node -> rel }.
linked (g : graph2) = {
  touches : g.node -> rel.
  touches X :- g.edge X _.
  touches X :- g.edge _ X.
}.
p : graph2 -> program = programOf linked.
```
