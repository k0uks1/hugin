# E0930: integer out of the object range

A meta integer used as object code does not fit into the object level's 64-bit `int`.

## Example

```hugin fail=E0930
big : int = 9223372036854775807.
next : int = big + 1.
size : int -> rel.
size next.
```

## Why this is an error

Meta integers are unbounded: the meta `int` is an inductive family, like Lean's `Int`
([`std/int`](https://k0uks1.github.io/hugin/reference/std/int.html)), and `big + 1` is
9223372036854775808. Object integers are 64-bit, from −9223372036854775808 to 9223372036854775807. A meta
integer is checked against this range where it becomes object code: where it is persisted as a literal,
lifted inside a value of a shared data type such as a list, or reflected as the literal of a `tint` term
([Staging](https://k0uks1.github.io/hugin/reference/meta/staging.html#lifting)). The compiler never wraps
the value around. Arithmetic in object code whose operands are meta values is computed exactly at compile
time, so only its result is checked: `size (big * 2 / 2)` is `size 9223372036854775807`.

## How to fix it

Compute a value that fits, or test the range with `fits64` of `std/int` and use object code only where
the value fits:

```hugin
big : int = 9223372036854775807.
next : int = big + 1.
size : int -> rel.
size (if (fits64 next) next big).
```

## Related

E0003 (integer literal out of range): an object integer literal beyond 64 bits.

by zero in object code.
