# E0957: run whose certificate is rejected

The checker of `hugin run --certify` rejects the run: a fact is not derived by a rule from the facts
given as its premises, or a rule derives a fact that the run does not report.

## Example

```hugin fail=E0957 certify
%use "std/certify".
word : string -> rel.
%input word.
early : string -> rel.
early W :- word W, W < "m".
```

```facts
word "apple".
word "pear".
```

## Why this is an error

A certified run guarantees that its facts are exactly the least (or, with negation, the perfect) model
of the program from its input facts, without trusting the engine: the checker of
[`std/certify`](https://k0uks1.github.io/hugin/reference/std/certify.html) builds a derivation of every
fact and checks that the facts are closed under the rules. If it cannot, the run is not certified. The
checker interprets equality and disequality on all values, but the order comparisons `<`, `<=`, `>` and
`>=` on integers only, as `std/semantics` does (the order of strings and floats is not modelled): here it
cannot derive `early "apple"`. Any other rejection is a fault of the engine.

## How to fix it

Compare integers, here a rank given with each word:

```hugin certify
%use "std/certify".
word : string -> int -> rel.
%input word.
early : string -> rel.
early W :- word W R, R < 13.
```

```facts
word "apple" 1.
word "pear" 16.
```
