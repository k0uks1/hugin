# E0948: rule name that does not fit

A rule name `r.k` (or a rule's label) names no rule of the program, names a rule whose head is not the
goal's relation, is given the wrong number of premises or a variable the rule does not have, is used
where no derivation of a judgment is expected, or, in an expression, has a comparison that does not
evaluate to true.

## Example

```hugin fail=E0948
%use "std/graph".
%use "std/semantics".
oneStep : {x y : G.node} -> tc G ⊢ G.edge x y -> tc G ⊢ path x y.
oneStep E = path.3 E.
```

## Why this is an error

The rules of a relation `r` are `r.1`, `r.2`, … in the order of the program, and a label `@n` adds the
name `n` (see [`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html#rule-names)).
A rule name stands for the derivation `fire` by that rule, with its premises in body order, so the goal
must be a fact of the rule's head relation, and the expected type must be a judgment whose program's
rules are known. The transitive closure `tc` has two rules for `path`: `path.1` (`path X Y :- g.edge X
Y.`) and `path.2`.

## How to fix it

Use a rule of the goal's relation, with a premise for each atom of its body:

```hugin
%use "std/graph".
%use "std/semantics".
oneStep : {x y : G.node} -> tc G ⊢ G.edge x y -> tc G ⊢ path x y.
oneStep E = path.1 E.
%opaque oneStep.
```
