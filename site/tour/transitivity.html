The closure tc builds paths from the left: an edge, then a path. Transitivity, joining two arbitrary paths, is not one of its rules; it is a property of what the rules derive, and it needs a proof by induction.

tcTrans recurses on the derivation of the first path. If it is an edge (path.1 E), the second rule applied to that edge and the second path gives the result. If it is an edge followed by a path (path.2 E P), the rule's middle variable Y is in scope, P derives path Y y, and the recursive call joins P with Q. The call is on a sub-derivation, so the recursion terminates.

The statement is about the program as written: change a rule of tc, and the proof is checked against the new rules. The wrong version below returns P instead of the recursive call; the compiler reports that it derives path Y y where path Y z is needed.

Try: replace the right side of the second clause with ?. The compiler reports the goal, tc G ⊢ path x z, with the variables in scope. Or delete the first clause, and see the missing case.

What is proved. For every graph G, every input database and all nodes x y z: if tc G derives path x y and path y z, it derives path x z. What is trusted. That a run of an instance of tc prints exactly the derived facts (adequacy).
