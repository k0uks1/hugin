# E0961: judgment over a program with negation or aggregates

A judgment `P ⊢ r t̄` is about a program that has a negation or an aggregate in the body of a rule.

## Example

```hugin fail=E0961
%use "std/semantics".
city : type. berlin, paris : city.
road : city -> city -> rel.
closed : city -> rel.
m = {
  open : city -> rel.
  open X :- road X _, not closed X.
}.
openIn : {x : city} -> m ⊢ open x -> Type.
openIn _ = Type.
```

## Why this is an error

The judgment notation stands for `derives` of `std/semantics`, the derivations of the positive fragment:
atoms and comparisons in bodies (see
[`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html#the-judgment-notation)). A
rule with a negation or an aggregate never fires in `derives`. For the program `m`, `m ⊢ open berlin`
would have no derivation, although running `m` with a road from berlin derives `m.open berlin`: a
judgment over such a program states facts about a different program than the one that runs, and a proof
could contradict the run.

## How to fix it

State the fact in the perfect model of the program with `perfect` (or a stratum's derivations with
`nderives`) of [`std/strata`](https://k0uks1.github.io/hugin/reference/std/strata.html), which read
negations and aggregates in the strata below:

```hugin
%use "std/semantics".
%use "std/strata".
%use "std/quote".
city : type. berlin, paris : city.
road : city -> city -> rel.
closed : city -> rel.
m = {
  open : city -> rel.
  open X :- road X _, not closed X.
}.
openIn (d : db) (x : ⇑city) : Type = perfect (programOf m) d (atom (own 0) [v x]).
```
