# E0204: signature mismatch

A module does not match a signature: an argument the parameter signature of a functor, a definition its
ascription, or a file its export signature (`%export`).

## Example

```hugin fail=E0204
graph : Type = { node : type, edge : node -> node -> rel }.
tc (g : graph) = {
  path : g.node -> g.node -> rel.
  path X Y :- g.edge X Y.
  path X Z :- g.edge X Y, path Y Z.
}.
city : type.
road : city -> city -> rel.
weight : city -> city -> int -> rel.
bad = tc { node = city }.
```

## Why this is an error

A module passed to a functor must provide every field its parameter's signature declares, at the
declared meta types (missing fields and constructor arities are compared). Extra fields are allowed. The
same holds for an ascription `m : S = e.` and for the export signature `%export S.` of a file, whose
declarations must provide every field of `S`; the diagnostic then notes that the file does not match its
`%export`. See [Modules](https://k0uks1.github.io/hugin/modules.html#signatures).

## How to fix it

Pass a module with every field of the signature:

```hugin
graph : Type = { node : type, edge : node -> node -> rel }.
tc (g : graph) = {
  path : g.node -> g.node -> rel.
  path X Y :- g.edge X Y.
  path X Z :- g.edge X Y, path Y Z.
}.
city : type.
road : city -> city -> rel.
weight : city -> city -> int -> rel.
ok = tc { node = city, edge = road }.
```
