# E0924: unsolved goal

An expression contains a typed hole `?` or `?name`: a part of the program that is still to be written.

## Example

```hugin fail=E0924
nat : Type.
zero : nat.
suc : nat -> nat.
plus : nat -> nat -> nat.
plus zero N = N.
plus (suc M) N = suc ?rest.
```

## Why this is an error

A hole stands for an expression of the type its position expects, its *goal*. The compiler checks the
rest of the item with the hole as an unknown, and reports the goal with the variables in scope, so a
program can be written step by step: write `?` where an expression is missing, read the goal, and replace
the hole by an expression of that type. Every hole of the program is reported, each once; a hole never
reaches object code, since the compilation stops before staging. The language server shows the goal when
hovering over the hole and offers code actions (case splits, missing clauses) that insert holes.

## How to fix it

Replace the hole with an expression of the goal's type:

```hugin
nat : Type.
zero : nat.
suc : nat -> nat.
plus : nat -> nat -> nat.
plus zero N = N.
plus (suc M) N = suc (plus M N).
```
