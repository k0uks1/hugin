# E0917: invalid quoted syntax

A quote `'{ … }` (or a directive's argument, which is quoted implicitly) uses a form of object syntax
that has no reflective representation, its content is not of the category the expected type needs, or
a hole is in the wrong place.

## Example

```hugin fail=E0917
p : int -> rel.
q : int -> rel.
r : rule = '{ p X :- (q X as F) }.
```

## Why this is an error

A quote denotes data of the prelude's reflective types (the reference,
[reflection](https://k0uks1.github.io/hugin/reflection.html)), which represent object variables,
literals, object constants applied to terms, arithmetic, comparisons, `not`, `,`, `;` and aggregates.
Other forms (`as`, ascriptions, projections, functional updates) have no representation yet.

The expected type gives the category of the content: a `module` (or `list rule`) quote holds items with
their periods, as in a file; a `rule` or `item` quote holds one item (its period is optional); a
`formula`, `term`, `sym`, `decl` or `measure` quote holds one of them, without `:-` or a period. A list
of formulas or terms is a meta list of quotes (`['{ p X }, '{ q X }]`).

The holes have rules of their own, and exist only inside a quote (outside, `$x` is the staging splice):
`$..Xs` stands for a sequence (the arguments of an atom, the body of a rule, the items of a module) and
cannot stand for a single element; in a pattern it must end its sequence; a hole in a pattern binds a
variable (`$X`) or matches anything (`$_`); the arguments of a higher-order hole `$F[V]` in a pattern
are variables bound by an enclosing aggregate. Without the prelude (`--no-prelude`) the reflective
types are not in scope at all.

## How to fix it

Write the code in the represented forms, for example with an equation instead of `as`:

```hugin
p : int -> rel.
q : int -> rel.
r : rule = '{ p X :- q X }.
```
