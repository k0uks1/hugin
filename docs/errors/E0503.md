# E0503: input position is not a pattern

**Retired** (redesign step C3): relations have no modes. The guard `r.check …` that `%demand` adds to a rule of `r` is an ordinary atom, so the inputs of the head may be computed (`r (N + 1) F :- edge N F` is guarded by `r.check (N + 1)`, evaluated once `N` is bound). 

An input position of the head of a moded relation is not a pattern.

## Example

```hugin fail=E0503 ignore
edge : int -> int -> rel.
fib : (n : int) -> (f : int) -> rel.
%mode fib +n -f.
fib (N + 1) F :- edge N F.
```

## Why this is an error

The inputs of a moded relation's head are matched against the call's demand, so they must be patterns:
variables, literals and constructor terms. Arithmetic, projections and updates cannot be matched; bind
them in the body instead.

## How to fix it

```hugin ignore
edge : int -> int -> rel.
fib : (n : int) -> (f : int) -> rel.
%mode fib +n -f.
fib M F :- edge N F, M = N + 1.
```
