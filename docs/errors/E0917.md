# E0917: invalid quoted syntax

Object syntax written where a reflective type (`term`, `formula`, `rule`, `item`, `module`) is expected
uses a form that has no reflective representation, or a hole is in the wrong place.

## Example

```hugin fail=E0917
p : int -> rel.
q : int -> rel.
r : rule = (p X :- (q X as F)).
```

## Why this is an error

Object syntax in a position of a reflective type is *quoted*: it denotes data of the prelude's
reflective types (the reference, [reflection](https://k0uks1.github.io/hugin/reflection.html)), which represent object variables, literals, object constants
applied to terms, arithmetic, comparisons, `not`, `,`, `;` and aggregates. Other forms (`as`,
ascriptions, projections, functional updates, named patterns) have no representation yet.

The holes have rules of their own: `$..Xs` stands for a sequence (the arguments of an atom, the body of a
rule, the elements of a list) and cannot stand for a single element; in a pattern it must end its
sequence; a hole in a pattern binds a variable (`$X`) or matches anything (`$_`); the arguments of a
higher-order hole `$F[V]` in a pattern are variables bound by an enclosing aggregate. Without the
prelude (`--no-prelude`) the reflective types are not in scope at all.

## How to fix it

Write the code in the represented forms, for example with an equation instead of `as`:

```hugin
p : int -> rel.
q : int -> rel.
r : rule = (p X :- q X).
```
