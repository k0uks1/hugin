# E0901: mismatched types

A term does not have the type its position expects.

## Example

```hugin fail=E0901 elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
n : int = zero.
```

## Why this is an error

The meta level is dependently typed: every term is checked against the type its position expects,
by unification. A mismatch, including an occurs-check failure such as self-application, is reported with
the expected and the found type, each as written: a definition by its name (`vec2`, not its value). If
the two look the same that way, both are shown with definitions replaced by their values.

Object code is the exception to unification: `⇑A` is accepted where `⇑B` is expected if `A` is a subtype
of `B` (`⇑` is covariant), so a mismatch of two lifted object types means that `A` is not a subtype of `B`.
Quoted terms are covariant in the same way: `quoted A` is accepted where `quoted B` or a `term` is
expected if `A` is a subtype of `B`. Object code at an object position is checked by object typing
instead ([E0402](E0402.md)).

A `quoted A` is accepted where a `formula` is expected only if `A` is a type of facts (a typed atom); for
another type, such as `quoted int`, the mismatch carries a note saying so. See
[Reflection](https://k0uks1.github.io/hugin/reference/reflection.html#typed-atoms).

A type that needs the value of a function or a definition of its own cycle does not compute: inside a
cycle of items that refer to each other, no body unfolds ([Order of
elaboration](https://k0uks1.github.io/hugin/meta/index.html#order-of-elaboration)). The mismatch then
names, in a note, the application that did not reduce and the cycle, whatever the order in which
the items are written:

```hugin fail=E0901 elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
vec : Type -> nat -> Type.
vnil : vec A zero.
vcons : A -> vec A N -> vec A (suc N).
vlen : vec A N -> nat.
vlen vnil = zero.
vlen (vcons X Xs) = suc (vlen Xs).
d : vec int (k zero) = vcons 1 vnil.
k : nat -> nat.
k zero = suc zero.
k (suc N) = vlen d.
```

The fix is to break the cycle, here by giving `d` a type that does not need `k`. An application of a
function that the termination check rejected ([E0912](E0912.md)) does not reduce either, and the note
says so.

The right-hand side of a clause is checked in the clause's own context, without the refinement made by
the clauses before it: after `w zero X = true.`, the clause `w N X = X.` has `X : sel (isz N)`, not
`sel (isz (suc _))`. If the right-hand side checks at every case of the case tree that uses the clause,
the error has a fix that writes those cases as clauses (`w (suc _) X = X.`).

## How to fix it

Declare the type that the value has:

```hugin elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
n : nat = zero.
```
