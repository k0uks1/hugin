# E0933: no candidate of the operator or opened name fits

An operator of the meta level denotes meta functions (`%infix op f.`), or a name is opened by `%use`
items for several meta constants, but none of them fits the types where it is used; or the operator
denotes nothing there.

## Example

```hugin fail=E0933
%use "std/nat".
both : bool = true + false.
```

## Why this is an error

`+` denotes `plus : nat -> nat -> nat` in a file that opens `std/nat`, and the result of `plus` is not
a `bool`. The arithmetic operators have built-in meanings on meta integers, floats and strings, and
`e + k` is the successor on a nat-like type; elsewhere an operator means only what its bindings say (see
[Operators bound to meta
functions](https://k0uks1.github.io/hugin/reference/lexical-structure.html#operators-bound-to-meta-functions)).
The message lists the bindings in scope with their types.

`≡` (ASCII `==`) has no built-in meaning: it is the equality `eq` of `std/eq` where that file is opened,
and nothing in object code, whose formulas compare with `=`.

```hugin fail=E0933
same : (n : nat) -> n ≡ n.
```

```hugin fail=E0933
p : int -> rel.
p 1.
q : int -> rel.
q X :- p X, X == 1.
```

## How to fix it

Use an operator whose binding fits, or a function by its name:

```hugin
%use "std/nat".
both : bool = if true true false.
```

Open `std/eq` for `≡`, and compare object values with `=`:

```hugin
%use "std/eq".
same : (n : nat) -> n ≡ n = [n] refl.
p : int -> rel.
p 1.
q : int -> rel.
q X :- p X, X = 1.
```

### Opened names

A name that `%use` items open for several meta constants is chosen in the same way (see [Overloaded
opened names](https://k0uks1.github.io/hugin/reference/modules.html#overloaded-opened-names)). Here
neither `decide` returns a `nat` after two arguments: that of `std/semantics` returns a derivation, the
generic one of `std/decide` a function.

```hugin fail=E0933
%use "std/nat".
%use "std/decide".
%use "std/semantics".
wrong : nat = decide 3 tt.
```

Apply the name as one of its declarations' types says:

```hugin
%use "std/eq" (tt).
%use "std/decide".
%use "std/semantics".
city : type. berlin, paris : city.
trip = { hop : city -> city -> rel. hop berlin paris. }.
direct : trip ⊢ hop berlin paris = decide 1 tt.
```
