# E0945: atom of a judgment that does not fit its program

The atom of a judgment `P ⊢ r t̄` does not name a relation of the program `P`, of its parameters or of the
file, gives a wrong number of arguments, or is not an atom. The program does not load `std/semantics`,
which defines the judgment.

## Example

```hugin fail=E0945
%use "std/graph".
%use "std/semantics".
city : type.
road : city -> city -> rel.
oneStep : {x y : G.node} -> tc G ⊢ G.edge x y -> tc G ⊢ route x y.
```

## Why this is an error

`P ⊢ r t̄` stands for `derives (programOf P) d (atom ρ [v t̄])` of
[`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html#the-judgment-notation). The
relation `r` is resolved as the rules of `P`'s body name relations: a relation the body declares (`path`
of `tc`), a relation of a functor's parameter through the argument the judgment writes (`G.edge` in
`tc G ⊢ …`; not `g.edge`, the functor's own name of its parameter, which the statement does not write), or
an object relation of the file (`road`). A relation of the file written as the value of an argument
that is not a variable, `road` in `tc { node = city, edge = road } ⊢ road x y`, is the parameter's
relation for the program, so naming it in the atom is an error too. `tc` has no relation `route`. The arguments are checked against the relation's columns, so their number
must be the relation's arity, and the notation needs the library that defines the judgment.

## How to fix it

Name a relation of the program, with an argument for each column:

```hugin
%use "std/graph".
%use "std/semantics".
oneStep : {x y : G.node} -> tc G ⊢ G.edge x y -> tc G ⊢ path x y.
oneStep E = path.1 E.
%opaque oneStep.
```
