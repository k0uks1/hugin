# E0932: ambiguous operator or opened name

An operator of the meta level has several bindings in scope (`%infix op f.`), or a name is opened by
`%use` items for several meta constants, and more than one of them fits the types where it is used.

## Example

```hugin fail=E0932
%use "std/nat".
%use "std/int".
add = [x] [y] x + y.
```

## Why this is an error

`+` denotes `plus` of `std/nat` and `iplus` of `std/int` in a file that opens both. The binding is chosen
by the types: a binding whose result does not fit the expected type is left out, then one whose argument
does not fit the type of the left operand (see [Operators bound to meta
functions](https://k0uks1.github.io/hugin/reference/lexical-structure.html#operators-bound-to-meta-functions)).
Here the types of `x` and `y` are not known, so both bindings fit, and the program does not say which
function it means. As Idris 2 does for an overloaded name, the compiler reports the ambiguity instead of
picking one.

## How to fix it

Give the type of an operand, or of the definition:

```hugin
%use "std/nat".
%use "std/int".
add : nat -> nat -> nat = [x] [y] x + y.
```

Or apply the function by its name:

```hugin
%use "std/nat".
%use "std/int".
add = [x] [y] plus x y.
```

### Opened names

A name that `%use` items open for several meta constants is chosen in the same way (see [Overloaded
opened names](https://k0uks1.github.io/hugin/reference/modules.html#overloaded-opened-names)): by the
result after the given arguments against the expected type, then by the first explicit argument's type.
`std/decide` and `std/semantics` both declare `decide`; used alone and without an expected type, either
fits:

```hugin fail=E0932
%use "std/decide".
%use "std/semantics".
which = decide.
```

Both are functions, so an expected function type does not choose either. Apply the name to an argument
whose type decides, here a decider, or open only the one that is meant:

```hugin
%use "std/decide".
%use "std/semantics".
which = decide natEqual.
```

```hugin
%use "std/decide".
%use "std/semantics" (holds).
which = decide.
```
