# E0946: functor written alone before `⊢`

A judgment `P ⊢ r t̄` has a functor written alone as its program `P`, without its arguments.

## Example

```hugin fail=E0946
%use "std/graph".
%use "std/semantics".
oneStep : {x y : G.node} -> tc ⊢ G.edge x y -> tc ⊢ path x y.
```

## Why this is an error

The program of a judgment is a functor applied to arguments, a module, or a value of type `program`
(see [`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html#the-judgment-notation)).
A functor alone is none of these: `tc` is a function from graphs to modules, and the judgment would have
to invent a name for its parameter. No name is bound that the statement does not write, so the
functor's arguments are written out.

## How to fix it

Apply the functor. In the type of a declaration, a free uppercase variable as the argument is bound as an
implicit argument, like any other, and its type is the type of the functor's parameter; the same variable
shares the graph between judgments, `tc G ⊢ …` and `tc2 G ⊢ …`:

```hugin
%use "std/graph".
%use "std/semantics".
oneStep : {x y : G.node} -> tc G ⊢ G.edge x y -> tc G ⊢ path x y.
oneStep E = path.1 E.
%opaque oneStep.
```
