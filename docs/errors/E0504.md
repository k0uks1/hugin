# E0504: fact constructor built in a moded input

An input argument of a call of a moded relation contains a term of a `%fact` constructor.

## Example

```hugin fail=E0504
shape : type.
%fact square : int -> shape.
area : (s : shape) -> (a : int) -> rel.
%mode area +s -a.
area (square N) A :- A = N * N.
q : int -> rel.
q A :- area (square 4) A.
```

## Why this is an error

The demand transformation builds the inputs of a call, which would make a term of a `%fact` constructor
a fact, so `%mode` would change the database. Remove `%fact` if the constructor is only used as a value,
or bind an existing fact to a variable first (`S = square 4`, an existence check) and pass the variable.
Input columns of the moded relation's own rule heads are patterns and are not affected.

## How to fix it

```hugin
shape : type.
%fact square : int -> shape.
square 4.
area : (s : shape) -> (a : int) -> rel.
%mode area +s -a.
area (square N) A :- A = N * N.
q : int -> rel.
q A :- S = square 4, area S A.
```
