# E0401: no value can occur in all these positions

The expected types of a variable have an empty meet.

## Example

```hugin fail=E0401
city : type.
person : type.
lives : person -> city -> rel.
both : rel.
both :- lives X _, lives _ X.
```

## Why this is an error

The type of a variable is the meet (the greatest common subtype) of the types of all the positions it
occurs in. Here `X` is a `person` in one atom and a `city` in the other; no value is both, so the rule
could never fire.

The same holds for a hole `$X` of type `quoted A` that occurs several times in the body of a quote: its
occurrences are one variable, whose type is the meet of their positions and of `A`. Here the data in
`$X` would have to be both a `teacher` and a `janitor`:

```hugin fail=E0401
staff : type.
teacher : (name : string) -> staff.
janitor : (name : string) -> staff.
teaches : teacher -> rel.
cleans : janitor -> rel.
busy : rel.
both : quoted staff -> rule.
both X = '{ busy :- teaches $X, cleans $X }.
```

See [Reflection](https://k0uks1.github.io/hugin/reflection.html#quotes).

Variables are typed again after staging, where meta code put object code into the rule. In the following
program `isVar X` stages to `vars X`, so `X` is a `num` and a `var`; the error is reported then. See
[Object types](https://k0uks1.github.io/hugin/object/types.html#staged-items).

```hugin fail=E0401
expr : type.
num : (n : int) -> expr.
var : (name : string) -> expr.
vars : (v : var) -> rel.
nums : (n : num) -> rel.
isVar : ⇑expr -> ⇑prop.
isVar E = vars E.
odd : rel.
odd :- nums X, isVar X.
```

## How to fix it

Use `X` in positions of the same type:

```hugin
city : type.
person : type.
lives : person -> city -> rel.
both : rel.
both :- lives X _, lives X _.
```
