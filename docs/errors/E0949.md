# E0949: `given` for a relation that is not an input

`given I` derives a fact of a relation that is not an input of the program: the program has rules for it.

## Example

```hugin fail=E0949
%use "std/graph".
%use "std/semantics".
fromInput : {x y : G.node} -> D (atom (own 0) [v x, v y]) -> tc G ⊢[D] path x y.
fromInput F = given F.
```

## Why this is an error

`given I` is the derivation of a fact of an input relation from the database (see
[`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html#rule-names)). The input
relations of a module's program are those of its parameters, those outside it, and its own relations
without rules. `path` has rules, so its facts are derived by them, never taken from the database:
`given` for it would need a proof of `so false`, the empty family.

## How to fix it

Derive the fact by a rule of its relation, from a fact of an input relation:

```hugin
%use "std/graph".
%use "std/semantics".
fromInput : {x y : G.node} -> D (atom (arg "edge") [v x, v y]) -> tc G ⊢[D] path x y.
fromInput F = path.1 (given F).
%opaque fromInput.
```
