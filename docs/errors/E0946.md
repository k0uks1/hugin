# E0946: functor parameter that cannot be generalised

A functor is written alone before `⊢`, and its parameter cannot become an implicit binder of the
declaration: another functor's parameter of the same name has another type, the parameter has no name, or
the judgment is not in the type of a declaration and the parameter is not in scope.

## Example

```hugin fail=E0946
%use "std/graph".
%use "std/semantics".
heavy (g : weighted) = {
  big : g.node -> rel.
  big X :- g.edge X X 9.
}.
both : {x : g.node} -> tc ⊢ path x x -> heavy ⊢ big x.
```

## Why this is an error

In the type of a declaration, `tc ⊢ path x y` stands for `tc g ⊢ path x y`, and the functor's parameter
`g` becomes an implicit binder `{g : graph}` of the declaration (see
[`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html#generalisation)).
Parameters of the same name are one binder, so `tc ⊢` and `tc2 ⊢` share `g`. `tc`'s parameter `g` is a
`graph` and `heavy`'s a `weighted`, so they cannot be one binder.

## How to fix it

Apply one of the functors to an argument of its own, here a binder `w`:

```hugin
%use "std/graph".
%use "std/semantics".
heavy (g : weighted) = {
  big : g.node -> rel.
  big X :- g.edge X X 9.
}.
both : {w : weighted} -> {x : g.node} -> {y : w.node} -> tc ⊢ path x x -> heavy w ⊢ big y -> tc ⊢ path x x.
both P H = P.
%opaque both.
```
