# E0918: reflection failure

Reflective data that should become object code (in an item `$e.`, or as a formula or term in object
code) is not known at compile time, or does not describe object code.

## Example

```hugin fail=E0918
p : int -> rel.
opaque : formula.
$'{ p 1 :- $opaque. }.
```

## Why this is an error

Reflection (the reference, [reflection](https://k0uks1.github.io/hugin/reflection.html)) turns data of the reflective types back into object code while the
program is elaborated: the data is evaluated, and the object code it describes is elaborated and checked
like code written by hand. This needs the data to be closed: built from the constructors of the
reflective types, literals and references to object constants. A postulate, or a parameter of a meta
function, is not known at that point. Data built with the constructors directly can also describe
something that is not object code: a variable without a name, a rule without heads, a bound variable
outside the aggregate that binds it.

## How to fix it

Reflect a value that the compiler can compute, for example a definition:

```hugin
p : int -> rel.
q : int -> rel.
known : formula = '{ q 1 }.
$'{ p 1 :- $known. }.
```
