  • Naming a relation passed as a non-variable argument is E0945

    P7c · L28L30

    In tc { node = city, edge = road } ⊢ road x y, road would be read as the file's ext road, while the program reads the same relation as arg "edge". That is a different statement. Following P9a's precedent (a silently different meaning becomes an error), an atom whose relation is the value of a non-variable argument, or of a field of a record literal written as one, is E0945. The match is by resolved constant and purely syntactic. The help points to tc G ⊢ G.edge … or an instance.

    Alternative: resolve road to arg "edge" by matching argument values. That needs name resolution by value.

  • How negated premises appear in rule names

    P9c · decision 6 · §6.3.1P9c

    Decision 6 left this to a short addendum. The P9c agent wrote it, and you have not reviewed it on its own. A rule name has one written premise per atom, negated atom and aggregate, in body order; comparisons are not written. A pattern binds a negated premise as the raw absent … value, because Hugin has no view patterns. In an expression, a negated atom without local variables takes a refutation P ⊢ q t̄ -> empty, which the elaborator wraps with absentOf k j tt; with local variables it takes the raw premise. An aggregate is written as its witness record in both positions.

    The cost is an asymmetry: patterns see absent … and expressions take a refutation. The library lemma refuted converts, with explicit strata.

  • decide does not prove stratified judgments

    P9c · §6.3P9c

    §6.3 said P9c connects decide to perfectHolds through the adequacy lemma. That is not possible in general. The judgment's database is the anonymous one, so it is arbitrary, while perfectHolds decides only at memOf ins, and the perfect model is not monotone. Instead std/certify has judgedHolds n p ins r vs k tt tt : judged p k (memOf ins) (atom r vs), for a database of listed facts. For positive programs, decide works as before.

  • E0961 still exists, for files without std/strata

    P9c · decision 6P9c

    Decision 6 said the stratified reading replaces E0961. A file that loads std/semantics but not std/strata cannot express nderives, so a judgment over a program with negation or aggregates is still E0961 there, with an updated message.

  • Unqualified own atoms are relations and structs only

    P9g · §2.1P9g

    §2.1 lists relations, structs and constructors as owned. P9g coerces only relations and structs when they are written unqualified, the kinds E0960 covers. An applied constructor in a type is not E0960 today, so coercing it would change the meaning of code that is accepted now. Also, an own relation of a body written inside a nested body is not coerced; there it is the nested body's E0960.

  • Member access without an instance is narrower than §4.3.4

    P9g · decision 9P9g

    (f ā).m is read without an instance only when f's definition is literally [x̄] { … } (read from the term, never evaluated) and m is in the body's free set. That set is the greatest set of meta members that resolve no object member and use only free members. It is conservative: a binder named like an object constant makes a member non-free. Every other (f ā).m keeps the old reading through an instance. A functor defined through another function never gets instance-free access.

  • Overloading of opened names: what it covers

    P9e · decision 8P9e

    The type-directed choice applies when two or more opened candidates are all meta constants. Object constants, which include an instance's relations reached through opened aliases, and directives keep E0109, so %use (tc g1). %use (tc g2). is still E0109. Beyond the design's head rule, candidates are first filtered by arity, also when there is no expected type. Two meta constants with identical types (two double : int -> int) now give E0932 instead of E0109. E0932/E0933 are reused and retitled "operator or opened name"; there are no new codes.

  • What the proof phase defers, and where E0962 reaches

    P9f · decision 4P9f

    The classification is syntactic and ignores binders, as the dependency order does. A local variable named like a program-dependent declaration can therefore defer a declaration that did not need it. That is harmless unless a rule uses it, which is then E0962. A file's %use, %infix and subtyping edges, and a body's object constants, are never deferred; if one of them needs a program-dependent name, that is E0962. A deferred object constant of a file is E0962 too. The design named only rules, queries and module-wide directives.

  • What the file's program here contains

    P9fP9f

    The file's own relations are its relations, structs, constructors and nullary object constants (berlin), in source order, as P7a numbers a body. Its rules are the assembled object items after module-wide directives. A file rule whose head is another module's relation makes here unreifiable. That is E0942 at each use of here, not at the rule.

  • The database pre-pass also reads record field types

    P9b · §2.5P9b

    §2.5 lists the declared type, arrow parts, binder types and arguments of global constants that take a universe or a family. P9b adds record field types, since they are binder types too. An owned atom in a field type therefore shares the declaration's anonymous database instead of getting its own unknown, which would be E0947 if nothing solved it.

  • Without std/semantics the coercion is off and the help does not say so

    P9bP9b CI fix

    So that a file without the library pays nothing for the pre-pass, the coercion is fully off without std/semantics. An owned relation in a meta type is then plain E0960. The help "load std/semantics" was dropped in the CI fix, so the message does not tell the user that loading the library would give the atom a meaning.

    Alternative: a cheap syntactic check that adds the library hint to E0960.

  • A program relation beats a file constructor of the same name in rule names

    P9d · §6.2P9d

    A nested fact is ext of the file's constructor, so r.k also names such heads by the constructor's name: drawn (circle R) :- big R. gives circle.1. If a relation of the program has the same name as a file constant, the program's relation wins. A label used where the goal's relation is not known names the rule's first head. A single-head rule after a rule with two heads of its relation is numbered after both (edge.3), so names agree with crule.index only for single-head rules, as §6.2 intended.

  • Edge case: an own relation inside a quoted type argument

    P9g · theoreticalP9g

    Parameter types are unknown before elaboration, so P9g's trigger counts every argument of an application in a type position as a type position. An own relation applied inside the type argument of quoted in a declaration's type therefore defers that declaration, although it states nothing about the program. If a rule then uses the declaration, the result is E0962. No test or library file has this shape.

  • Edge case: the anonymous database in a body-local application

    P9g · theoreticalP9g

    The pre-pass reads a body member's type at an application head (placed reached a.alpha in coarse's body). Where it cannot read a body-local function's parameter types that way, a coerced atom in its argument gets its own unknown database instead of the declaration's, and E0947 asks for ⊢[e]. Not observed in tests.

  • No sub in the semantics

    P5a · §7.2L14

    Nested facts are modelled as extra heads of a rule, not with a sub premise. A subfactOf relation would need meta code to take object code apart, which D13 (no modal foundation) rules out.

    Alternative: add sub later together with a code-inspection primitive.

  • The converse round trip is proved, not trusted

    P7a · D12L17

    Only unquote (quote c) ≡ c holds by computation. The converse is the proved lemma quoteUnquote, and it covers only data that quote produced. The general statement is false: qterm (tarith 1 2) unquotes to the code 3. Trusting it would make the logic inconsistent.

    P2b · L6L13

    You approved "^ 8 right". At the object level ^ is string concatenation at level 6, and one symbol should not parse differently at the two levels. Nothing in the library binds ^ yet.

  • cnot instead of cneg

  • in is a contextual keyword

    The agent reserved in. I overrode this, because in is a common Datalog relation name (membership). It only ends rewrite h in e, as contextual keywords do in C#, Rust and Kotlin.

Agent decisions per batch (condensed)

P1. %postulate only at top level. Trusted primitives are the %builtin operations plus native std/nat; --safe rejects postulates, not trusted primitives. The %assumptions NAME. directive was added. Index promotion is recomputed per constructor.

P8a. --export-proofs in CertifyingDatalog's format, pinned to v0.2.0. Negation and comparisons are exported as assumption leaves (the Gelfond–Lifschitz reduct). Unsupported constructs are left out with a warning. Proofs are of least depth, found deterministically.

P2. {x := e} follows Agda's rule. %opaque is its own kind of global, not a postulate. decEq uses the trusted primitives sameTrue/apart. uip holds by axiom K.

P3. The equation is named only on request (match H :). match/rewrite use std/eq when it is loaded, otherwise E0929. Numerals are treated as atoms during abstraction.

P4. int is a base type at the object level and an inductive family at the meta level. Division rounds toward zero; meta x/0 = 0, as in Lean. A value crossing into object code is range-checked (E0930). Native results are capped at 2^24 bits.

P2b. A binding has no precedence of its own, so parsing never depends on imports. A binding lives in the file of its function. Overloading compares the heads of types only and never backtracks. Patterns may only use operators bound to constructors.

P5a/b. Index unification on object code. Constructor applications, and later all applications, are checked against the expected type first. holds works from the empty database, and monotone carries the result to any database. Monotonicity is proved both in the database and in the rules; leastModel is a record of both directions.

P7a. std/quote is a separate library. Hygiene names are canonicalised by first occurrence. Syntax forms quotes could not express before (as, ascription, projection, update) were added. programOf is a contextual keyword; it reads the body with fresh variables and creates no instance.

P6. nderives/npremises read the completed lower strata, so they stay strictly positive. perfect is the iterated least fixpoint. Aggregate witnesses are a record-valued function. perfect is not monotone, which the test proves.

P7b. ⊢ elaborates to derives with no core rule. Program functions stay folded and are unified by their arguments first, as in Lean's lazy delta reduction. Rule names are pattern synonyms. Coverage splits into the program's rules. The adequacy statement is in the reference.

P9a. E0960 is raised wherever an applied relation is lifted into a meta type, partial applications included. E0961 is checked on the evaluated program value.

P8b. The checker certifies the program the engine ran. Soundness is the checker's result type. The model check closed is proved sound, which gives the least model for positive programs and the perfect model for stratified ones. Reflexivity is checked per fact, so no new primitive is needed. Stratified holds is provided by decidePerfect.

P7c (#210, bccf709). A functor written alone before ⊢ is E0946 with the help "write tc G ⊢ …", checked in a pre-pass so it is reported before {x : G.node} fails. Projections are not postponed, so variables written as functor arguments are unified early with the parameter types, and ⊢[D] variables with db. The anonymous database is a binder #db the lexer cannot produce, used only by the judgments without […] in the declaration's type and parameter types (matched by turnstile position); it prints as {_ : db} or _, and E0926 omits it. Elsewhere an omitted database is an unknown, E0947 if unsolved, reported before other unsolved unknowns. tc G ⊢ G.edge x y maps arguments to parameters by position and reads arg "edge" (arg "g.edge" for several parameters); g.edge is E0945; a non-variable argument names no relation (L30). Proof B uses placed D A and coarse A ⊢[D].

P9e (#211, 95f9e55). Names opened by several %use items are chosen when all candidates are meta constants. P9f (#212, 2ea0ed4). The phase is a split by dependencies, not by position (Lean, Isabelle and Agda get the order from the text; Hugin's items are unordered).
