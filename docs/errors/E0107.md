# E0107: not a module

A path `m.x` is used where `m` is not module-valued.

## Example

```hugin fail=E0107
limit = 3.
x = limit.lo.
```

## Why this is an error

Only modules (module bodies, imported files and functor applications) have members. Selecting a member
of a value of another meta type is an error.

## How to fix it

Select a member of a record:

```hugin
bounds = { lo = 0, hi = 3 }.
x = bounds.lo.
```

## A member that needs an instance

A functor applied to arguments with variables, `(f G).m`, has no instance: an instance is created where
a module is evaluated with closed arguments. A meta member that mentions no object constant of the body,
such as a lemma about its relations, is read without one (see
[Members without an instance](https://k0uks1.github.io/hugin/reference/modules.html#members-without-an-instance)).
A member that mentions an object constant, directly or through other members, needs one:

```hugin fail=E0107
%use "std/graph".
tc3 (g : graph) = {
  path : g.node -> g.node -> rel.
  path X Y :- g.edge X Y.
  relation : ⇑(g.node -> g.node -> rel) = path.
}.
pathOf : (G : graph) -> ⇑(G.node -> G.node -> rel).
pathOf G = (tc3 G).relation.
```

Apply the functor in a definition, which creates an instance, and select the member of the instance:
`fast = tc3 { node = city, edge = road }.` and `fast.relation`.
