# E0960: applied relation used as a meta type

A relation (or struct) applied to arguments is used where a meta type is expected, such as the type of a
parameter of a meta function, or under an explicit lift `⇑(r t̄)`; or a relation is used unapplied where a
family of meta types is expected, which would apply it.

## Example

```hugin fail=E0960
%use "std/graph".
%use "std/semantics".
city : type. berlin, paris : city.
road : city -> city -> rel.
%input road.
fast = tc { node = city, edge = road }.
same : {x y : city} -> fast.path x y -> fast.path x y.
same P = P.
```

## Why this is an error

A relation used as a type is its fact type, whose values are the identities of its facts (see
[Fact types](https://k0uks1.github.io/hugin/reference/object/types.html#fact-types)): `w : fast.path =
<fast.path berlin paris>.` is such an identity. An applied relation is not an object type, so under `⇑` it
would be the fact type of an application, which no object term has. The type of `same` would have no
values, and a theorem stated with it would prove nothing. The object level rejects the same text in an
object type (E0909).

Whether an atom holds is not a property of the relation alone: it depends on the program whose rules
derive it, and on the input facts. That proposition is a judgment (see
[`std/semantics`](https://k0uks1.github.io/hugin/reference/std/semantics.html#the-judgment-notation)).

## How to fix it

Name the program in a judgment, `P ⊢ r t̄`:

```hugin
%use "std/graph".
%use "std/semantics".
city : type. berlin, paris : city.
road : city -> city -> rel.
%input road.
fast = tc { node = city, edge = road }.
same : {x y : city} -> fast ⊢ path x y -> fast ⊢ path x y.
same P = P.
```

For a relation of a functor's parameter, such as `g.edge x y`, name a program over the parameter:
`tc ⊢ g.edge x y`.
