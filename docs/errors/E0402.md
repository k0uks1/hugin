# E0402: type mismatch

A term does not have a subtype of the expected type.

## Example

```hugin fail=E0402
person : type.
age : person -> int -> rel.
name : person -> string -> rel.
older : person -> rel.
older P :- age P A, name P N, A < N.
```

## Why this is an error

Every term must have a subtype of the type its position expects: a column, an operand of an
arithmetic operator, a comparison or an aggregate. Ints, floats and strings are never converted into each
other, and the head of a rule must be a relation atom.

Object code is checked where it is written: also in a meta function that returns object code, in a
formula function and in a quote `'( … )`, whether or not they are used. Meta code of type `⇑τ` inserted
into object code is a term of type `τ`: in a head `τ` must be a subtype of the column type, in a body
the two types must meet. In the following program `swap` puts its argument of type `⇑typ` in a column
of type `expr`, which is reported at `swap`. See
[Object types](https://k0uks1.github.io/hugin/reference/object/types.html#where-object-code-is-typed).

```hugin fail=E0402
expr : type.
typ : type.
typed : (e : expr) -> (t : typ) -> rel.
swap : ⇑expr -> ⇑typ -> ⇑prop.
swap E T = typed T E.
```

> **History.** Before issue #56 this was E0901, from unification, and object code in meta functions was
> checked only where it was used.

## How to fix it

Compare the age with an integer:

```hugin
person : type.
age : person -> int -> rel.
older : person -> rel.
older P :- age P A, A > 65.
```
