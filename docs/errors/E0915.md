# E0915: invalid pattern

A clause or pattern is malformed, or matching on it cannot be decided.

## Example

```hugin fail=E0915 elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
same : nat -> nat -> nat.
same N N = N.
```

## Why this is an error

Patterns are linear (each variable is bound once) and consist of constructors and variables; all clauses
of a function have the same number of patterns. On a nat-like type, integer literals and successor
patterns `P + k` (an integer literal `k` of at least 1) stand for constructor patterns; on another type,
and in another form with an operator (`N + 0`, `N - 1`, `N + M`), they are errors. See
[Clauses](https://k0uks1.github.io/hugin/reference/meta/clauses.html#patterns). Matching must be decidable by
unification: an index that is a stuck function application cannot be matched on.

A function needs a declaration with its type before it can have clauses. The clauses of a module body
belong to the functions that the body declares: a clause in a body for a function declared only outside
it has no declaration.

```hugin fail=E0915 elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
double : nat -> nat.
double zero = zero.
double (suc N) = suc (suc (double N)).
m = {
  double zero = zero.
}.
```

## How to fix it

Write a successor pattern with a literal of at least 1:

```hugin elaborate
pred : nat -> nat.
pred 0 = 0.
pred (N + 1) = N.
```

Use distinct variables in the patterns:

```hugin elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
first : nat -> nat -> nat.
first N M = N.
```

Declare the function in the body whose clauses define it:

```hugin elaborate
nat : Type.
zero : nat.
suc : nat -> nat.
m = {
  double : nat -> nat.
  double zero = zero.
  double (suc N) = suc (suc (double N)).
}.
```
